# Beta 5.2 — диагностическая проверка GM

Главное: предыдущие 1050 сообщений не считаются доказанно извлечёнными; завершённые блоки в старой Beta не сохраняли статистику сырых ответов. Нельзя по одному экспорту восстановить, были ли ответы модели пустыми или отброшены проверкой.

1. Сделать полный экспорт JSON до обновления.
2. Обновить расширение из этого ZIP. Импортировать экспорт назад НЕ нужно: сохранённые данные чата остаются на месте.
3. Открыть GM → Синхронизация. **Не** нажимать «Продолжить» или «Проверить весь чат».
4. Нажать «Проверить сообщения 1–10» (это **один** платный API-запрос, без создания фактов или изменения позиции).
5. Скопировать статистику: сколько «модель предложила», сколько «прошло проверку», причины отказов. Если Error Bad Request, будет показана причина, но без раскрытия серверного JSON, которого не было в ошибке.
6. Не запускать все 1124 сообщений, пока тест не покажет извлечение и в интерфейсе не появятся проверяемые предложения.

Новое:
- Аналитика классифицирует ошибки по недопустимому scope, message_ids, отсутствующей/несовпадающей цитате, отсутствию текста и дубликатам.
- Диагностический запрос ничего не записывает в GM, не увеличивает `syncRuns`, не передвигает `fullScan.cursor`, не трогает статусы фактов.
- В обычной полной проверке теперь нельзя молча пройти блок, если все полученные факты отвергнуты. Второй подряд явно пустой ответ останавливает полный проход, чтобы не платить за пустоту.
- При любых ошибках полный проход сохраняет cursor последнего действительно завершённого блока.
- Требуется корректная дословная цитата для автоматически предложенного факта.

Примечание: мы не меняли Connection Manager, роутинг API и настройки пресета. Ошибку HTTP 400 должен объяснить сервер провайдера; она может быть связана с конкретной порцией или параметрами, но не доказана одной надписью `Bad Request`.

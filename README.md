# Ena Desktop 2001 — v1.0 Beta

Отдельное браузерное расширение для SillyTavern, оформленное как Windows 2000. Лорный ноутбук Ены + НЕлорная GM-панель.

## Обновление существующего EnaJJBA-Desktop-ST

1. На всякий случай сделайте резервную копию чата SillyTavern и файла предыдущей версии расширения. Если v0.1/v0.2 ещё установлена, её НЕ нужно удалять.
2. В существующем GitHub-репозитории `amoktzx/EnaJJBA-Desktop-ST` обновите содержимое корня: `manifest.json`, `index.js`, `style.css`, папку `assets` и ДОБАВЬТЕ новые файлы `beta.js` и `betaCore.js`.
3. Убедитесь, что `manifest.json` в КОРНЕ, а не во вложенной папке.
4. В SillyTavern зайдите в Extensions / Manage Extensions и выполните обновление расширения с GitHub, потом обновите страницу браузера (Ctrl+F5).
5. Откройте ноутбук через плавающую иконку. На ПК иконки на рабочем столе открываются ДВОЙНЫМ кликом. Пуск → Выключить, календарь под временем.
6. Сразу проверьте: «Мой компьютер» → «ИИ и синхронизация», «GM» → «Синхронизация». До первых тестов включать автоматическую проверку необязательно.

Важно: расширение только для браузера, не требует редактирования серверного `config.yaml` или API-ключей в коде.

## Приложения

- **Архив**: фильмы, музыка, книги, аномальные носители, обложки, дата, личная копия, избранное, «надо пересмотреть», статусы просмотра, отметки стендовых аномалий. Коммерческие лицензии не добавляются в личный архив.
- **Видеосалон**: лицензии, копии для проката, общие финансовые операции, документы, задачи. НЕ автоматический учёт каждого посетителя. Суммы отображают только записанные движения, а не предполагаемый баланс.
- **Почта и SMS**: подтверждённые входящие, исходящие, черновики. Создание записи в этих каталогах само по себе НЕ отправляет письмо или SMS внутри сюжета. Прямая интеграция с Phone-ST пока не реализована.
- **Справочник**: люди и места — только информация, которую знает Ена.
- **Заметки**: свободный текст из v0.2 и отдельные редактируемые записи. Нейронка не сочиняет мысли Ены.
- **GM • вне сюжета**: финансовые операции, инвентарь, внешние следы и травмы, основные и побочные задания, знания NPC, хронология, нерешённые обстоятельства, предложения от ИИ, журнал изменений.
- **Мой компьютер**: обои, размер иконок, игровая дата, автоматическое открытие ноутбука по ролевой фразе, настройка интервала ИИ, JSON-экспорт/импорт.

## Настройка ИИ

В «Мой компьютер» → «ИИ и синхронизация» включите или выключите автоматическую проверку (ПО УМОЛЧАНИЮ ВЫКЛЮЧЕНА) и выберите интервал 25/50/75/100 сообщений. Можно вызвать вручную в GM → «Синхронизация» → «Проверить последние 50 сообщений».

Инструмент использует `SillyTavern.getContext().generateRaw()` **с текущим подключением ST**. Это значит, что при выбранном в самой ST OpenRouter, Route.me и т. п. вызовы идут через выбранный там профиль и выбранную модель. **Самостоятельный выбор второго API-профиля и автоматическое переключение моделей в этой бете НЕ реализованы**, чтобы не менять настройки основного рассказчика без вашего ведома. Отдельный ключ добавлять в расширение не надо.

1. Скрипт берёт блок сообщений, просит ИИ извлечь только факты с точными цитатами и индексами сообщений.
2. В GM появляются **предложения на подтверждение**. ИИ НЕ пишет напрямую в базе данных, даже если переключатель «спрашивать подтверждение» выключен (безопасный режим беты).
3. Вы подтверждаете каждое предложение или отклоняете его. Подтверждённые данные записываются в соответствующий каталог. При отсутствии подтверждённого факта нужно оставить каталог пустым.
4. Когда исходное сообщение удаляется, редактируется или меняется выбранный свайп, привязанные данные перестают отображаться. Система не удаляет эти записи безвозвратно; при восстановлении точного источника они появятся снова. Ручные записи без связи с сообщением не затрагиваются.

**Границы синхронизации:** пока это интеграция с событиями чата и вызовом модели SillyTavern, а НЕ прямой триггер из Memory Books Side Prompts. Интервал считается по новым сообщениям чата после первого запуска; автообработка предыдущих 1000 сообщений не включается. Для старой истории есть ручная проверка последних N сообщений. Для очень длинных сообщений берутся начало и конец; пропущенная середина требует ручной проверки. При смене чата во время запроса результат отбрасывается. В бете не стоит использовать ИИ-синхронизацию как единственный источник сюжетной истины.

## Данные, резервные копии, совместимость

Состояние хранится под прежним ключом `ena_desktop_v1` в метаданных каждого чата SillyTavern. Записи из старой v0.1/v0.2 автоматически копируются в новую схему **без удаления исходных записей**. Личный архив остаётся в старой структуре — поэтому обложки сохраняются. Крупные изображения могут увеличить размер сохранения чата; система сжимает обложки. Свои обои из файла — только в текущем браузере.

«Мой компьютер» → «Экспорт JSON» скачивает резервную копию данных чата. Импорт заменяет значения основных разделов выбранного чата **после подтверждения**, поэтому прежде создайте резервную копию.

Ролевой триггер в пользовательском сообщении: «Ена открыла ноутбук»; «Ена закрыла ноутбук». Двойной клик на иконки на ПК оставлен.

## Проверки

- `node tests.mjs`: проверка идентификаторов событий, удалений, правок, свайпов, смещения индексов и JSON-ответов.
- Локально в Chromium проверено: открытие UI, CRUD инвентаря/лицензий, редактирование, привязка к сообщению, подтверждение предложения ИИ, откат Архива при правке исходника и мобильный интерфейс. Это не заменяет проверки на конкретном хостинге SillyTavern.
- `DEMO_OFFLINE.html` — автономная демонстрация. Работает без API и без подключения к игровому чату; данные в ней тестовые/временные, не являются сюжетными.

## Ограничения beta

- Нет прямой двухсторонней синхронизации с Phone-ST или Memory Books (пока только события чата, выбранная модель, предложение фактов).
- Нет безопасного фонового переключения профиля модели; действующее API берётся из SillyTavern.
- Автоизвлечение зависит от качества LLM и не гарантирует полного понимания сцены.
- Источники сравниваются по полному отпечатку сообщения (дата, текст, выбранный свайп); новые ручные утверждения, ссылающиеся на изменённое сообщение, надо проверить повторно.
- Состояние приложения пока хранится в метаданных, а не в отдельной серверной базе; делайте экспорт перед большими обновлениями.

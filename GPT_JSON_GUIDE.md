# Как отредактировать полную базу Ena Desktop в ChatGPT

1. Открой **GM → Синхронизация → ⬇ Полный экспорт JSON**.
2. Прикрепи полученный файл в ChatGPT. Скажи, какие факты исправить, какие статусы изменить, что разделить и почему.
3. При правках используй единственный полный JSON-файл. Основные данные:
   - `data.beta.proposals` — ВСЕ предложения независимо от статуса `pending`, `approved`, `rejected`, `deleted`; `split` — внутренняя архивная отметка исходных составных предложений.
   - `data.beta.records` — принятые/ручные записи в банке, инвентаре, знаниях NPC и прочих справочниках; записи могут быть с `deleted: true`.
   - `data.archive.films`, `.books`, `.music`, `.anomalies` — личные карточки.
   - `data.beta.history` — сохранённый журнал действий, `fullScan`/`syncCursor` — прогресс анализа.
   - `data.salon`, `data.directory`, `data.notes` и другие разделы — остальные данные ноутбука.
4. **Сохраняй неизменными `id`, `sources[].key`, `linkedRecordId`, `proposalId`, `chatFingerprint`**, кроме случаев намеренной миграции. Не выдумывай отсутствующие сообщения-источники. Для смены статуса меняй именно `status` у нужного предложения.
5. В ChatGPT можно попросить: «Проанализируй базу, сохрани все ID и источники, убери ложные сведения, уточни принятые факты, верни полный валидный JSON без потерь».
6. В ноутбуке выбери **GM → Синхронизация → ⬆ Импорт JSON** и загрузи исправленный файл. Импорт **полностью заменит** данные текущего чата, предварительно автоматически выгрузив их резервную копию.
7. После импорта проверь списки GM и Архив и, при необходимости, сверяй сообщения источников. Утверждённые факты с отсутствующими источниками скрываются.

## Какое отличие статусов
- `pending` — ждёт решения, блокирует повторное обнаружение.
- `approved` — принятый факт, блокирует повторное обнаружение, представлен в каталоге.
- `rejected` — отказано, блокирует повторное обнаружение по тому же источнику и якорной цитате.
- `deleted` — запись в корзине; НЕ блокирует повторное обнаружение, не отображается в активных каталогах.
- `split` — техническая история разделения: не даёт исходному составному предложению появляться вновь.

**Не загружай в публичный GitHub экспорт сюжета:** он содержит содержание твоей ролевой истории. В сам экспорт API-ключи не включаются.

# Ena Desktop Beta 5.3 — chat reading and non-billable introspection

**Зачем:** диагностика Beta 5.2 показывала `no-message` на диапазонах 1–10 и 1051–1060, при этом старый full scan успел ошибочно отметить 1050 сообщений обработанными и извлечь 0 фактов.

## Исправления
- Добавлена кнопка **Чтение чата (0 API-запросов)** во вкладке GM → Синхронизация. Показывает число читаемых/системных/пустых сообщений и имена полей первых трёх объектов в нескольких диапазонах, не показывает и не пересылает содержание текста.
- Чтение сообщений теперь поддерживает `mes`, `text`, `content`, `message` и selected `swipes`. Для стандартного `mes` ключи исходных сообщений не меняются. Данные `is_system === true` всё ещё пропускаются.
- **Блок без читаемых реплик теперь ОСТАНАВЛИВАЕТ полный анализ**, вместо того чтобы молча увеличивать позицию и счётчик «завершено». Экспорт и статусы сохранены.
- Цитаты при ручном делении и редактировании также проверяются по новым текстовым полям.

## Что сделать
1. Сохранить полный экспорт JSON, заменить файлы расширения в том же GitHub-репозитории, обновить расширение и перезагрузить страницу.
2. GM → Синхронизация → **Чтение чата (0 API-запросов)**. Прислать показанные количества и структуру полей, чтобы подтвердить причину. Это не потребляет токены.
3. НЕ возобновлять прежний проход 1050/1124 до проверки показателей. Ранние «обработанные» блоки могут быть недостоверны.
4. После подтверждения чтения протестировать один короткий блок, затем новую полную проверку с сохранением старого JSON.

Ошибку API Bad Request на конкретном блоке это исправление само по себе не гарантирует устранить. Для неё потребуется текст ошибки из Network Response, если появится снова.

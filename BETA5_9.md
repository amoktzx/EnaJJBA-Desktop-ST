# Ena Desktop Beta 5.9 — Досье с вложенным гардеробом

## Главное изменение

**Гардероб — строка внутри досье каждого персонажа**. Отдельная вкладка `GM → Гардероб` убрана из панели, но внутренний тип `gm:wardrobe` сохранён в данных и редакторе, чтобы не сломать прошлые экспорты.

- В `GM → Досье` персонажи и животные собраны по имени. Внутри — строки `Глаза`, `Волосы`, `Рост`, `Кожа` и остальные подтверждённые поля; каждую строку можно редактировать через прежнюю кнопку.
- В конце каждого досье есть раскрывающаяся строка `Гардероб`. Внутри — отдельные вещи или комплекты, прежние источники и кнопка `+ Добавить вещь / комплект`.
- Старые записи о костюмах, случайно получившие категорию `gm:profiles` вместо `gm:wardrobe`, **показываются** под «Гардеробом». Записанная категория в JSON при этом не меняется автоматически.
- Одинаковые по описанию комплекты из двух старых разделов на экране сгруппированы; старые источники доступны в `Другие подтверждения комплекта`.
- Одна характеристика досье показывается одной строкой. Если позже выяснилось уточнение, предыдущее значение можно открыть в `Предыдущие сведения`. Ничего не удаляется при обычном подтверждении.
- Новое предложение одежды, ошибочно выданное моделью как `gm:profiles` с атрибутом комплекта/одежды, перенаправляется во внутренний `gm:wardrobe` **до записи**.
- Для прямого повторения уже сохранённого свойства или комплекта предусмотрен консервативный пропуск. Отличающееся подтверждённое значение характеристики маркируется как **уточнение**, не затирая исходный факт. Семантически похожие, но по-разному сформулированные факты всё ещё могут требовать ручной проверки.
- В списке предложений и диагностике рядом с полем появляется имя персонажа, а не бессмысленный заголовок вроде «высокая».

## Чего обновление намеренно НЕ делает

- Не объединяет автоматически «незнакомка», «Ена» и другие возможные имена, если их тождество не установлено; это надо поправить вручную до подтверждения.
- Не объявляет одежду постоянной собственностью персонажа только потому, что она была надета в одной сцене.
- Не отслеживает автоматически текущий наряд в реальном времени.
- Не подменяет Memory Books и не хранит настроение/романтику как объективные свойства.
- Не пытается оценивать смысл цитаты одной лишь строковой проверкой. Подтверждение остаётся за пользователем.
- Не гарантирует, что следующая генерация ИИ вернёт меньше или лучше фактов; локально проверяется структура и обработка, не удалённый провайдер.

## Обновление

1. Экспортировать резервный `EnaDesktop_FULL_....json` в старой Beta.
2. Заменить все файлы установленного расширения содержимым ZIP, включая **новый** `dossierIndex.js`, и перезагрузить SillyTavern.
3. Открыть `GM → Досье`. Ранее сохранённые комплекты должны отображаться внутри соответствующего досье; вкладки гардероба в шапке больше нет.
4. Открыть `GM → Синхронизация` и сделать диагностику сообщений 1–10. Пока не запускать полный проход — нужно проверить содержимое новых предложений.

## Безопасность данных и совместимость

Формат экспорта по-прежнему `ena-desktop-full-v2`; `records`, `proposals`, `history` и ссылки на источники не удаляются. Старые `gm:wardrobe` сохраняются в экспорте со своим scope. Никакая массовая миграция или автоматическое принятие 76 ранее неподтверждённых предложений не выполняется. Тесты проверяют чтение импорта, группировку, историю уточнений, диагностику и сохранение источников.
